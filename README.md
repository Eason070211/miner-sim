# PoW 挖矿模拟器 · 教学演示（仅本地运行）

一套**零依赖、纯 Python 标准库**的加密货币挖矿过程模拟器：真实执行 SHA-256
工作量证明（Proof of Work, PoW）的哈希与目标判定，但每次尝试之间强制睡眠，
所以**真实 CPU 占用率 ≈ 0%**，不连接任何矿池、不做任何真实挖矿、不产生任何
对外网络流量——这正是你要求的安全边界（localhost only）。

```
python main.py                  # 图形界面（推荐；若报 tkinter/Tcl 错误，改用 py main.py）
python run_headless.py --seconds 15   # 无界面演示 + JSON 报告 + 链完整性自检
python example_hash.py          # 最简真实运算示例：80 字节区块头哈希
```

> 注：部分环境里 `python` 指向不含 Tcl 的精简发行版，GUI 起不来时用 Windows
> 启动器 `py main.py`（本机验证过可用）。无界面脚本不受影响。

图形界面同时在本机开一个只读统计端口：<http://127.0.0.1:8332/stats>
（8332 正是 Bitcoin Core 主网 RPC 的默认端口，这里只读、只监听回环地址）。

## 一、你能在界面上看到什么

| 区域 | 内容 |
|---|---|
| 区块链视图 | 每个区块 = 一个方块，含哈希 / 前块哈希 / 矿工 / 交易数，箭头表示哈希链 |
| CPU 矿工 | 1 条流，逐个尝试 nonce；显示当前 nonce、尝试次数、算力、实时哈希 |
| GPU 矿工 | 4 条并行流（模拟 CUDA 核心并行搜索），出块速度约为 CPU 的 4 倍 |
| 当前哈希 | 前导零以绿色高亮——PoW 的判定标准就是"哈希小于目标" |
| 内存池 | 待打包确认的交易；每 ~2.5s 自动进来一笔新交易 |
| 事件日志 | 出块 / 新交易 / 难度调整等全部事件 |
| 控制 | 暂停 / 开始、重置、难度（1~3 个前导零）、动画延迟（10~1000 ms） |

默认"中等"难度（2 个前导零）下，期望约 3 秒出一个块，动画清晰可见。
把延迟拉到 1000 ms 可以慢慢看；把难度切到 3 个前导零会立刻体会到"挖矿变难
16 倍"是怎么回事。

## 二、代码结构

```
miner_sim/
├─ main.py          图形界面 + localhost 统计端口
├─ blockchain.py    区块 / 80 字节区块头 / 双重 SHA-256 / 目标判定 / 默克尔根 / 难度调整
├─ miners.py        CPU(1 流) / GPU(4 流) 矿工线程，nonce 按 lane 划分并行
├─ config.py        全部可调参数
├─ run_headless.py  无界面运行 + 链完整性自检
└─ example_hash.py  最简真实哈希示例
```

**核心机制（与真实比特币一致的部分）**：
- 区块头 80 字节 = version(4) + 前块哈希(32) + 默克尔根(32) + 时间(4) + bits(4) + nonce(4)
- 哈希 = `sha256( sha256( header ) )`（双重 SHA-256）
- 目标判定：`hash < target`；本模拟器里等价于"哈希前 N 位十六进制为 0"
- 出块奖励 3.125 BTC（2024 年 4 月减半后的时代，持续到约 2028 年下次减半）
- 难度自动调整：每 3 个区块看平均出块时间，过快则加难、过慢则放松

**与真实比特币的简化**：难度用"前导零个数"代替完整的 256 位难度编码；没有
P2P 网络、没有脚本验证、没有 UTXO 集合、没有分叉处理。

## 三、挖矿这条链，为什么能赚钱（2026-10 数据）

赚钱公式极简：

```
矿工期望日收入 = 全网日产出 × (你的算力 / 全网算力)
                 = 144块/天 × 3.125 BTC × 你的份额
成本 = 电费 + 硬件折旧 + 托管/散热/维护
```

**用今天的数字算一笔账**（数据截至 2026-10-16，来源见文末）：

| 项目 | 数值 |
|---|---|
| 比特币价格 | ≈ $82,000 |
| 全网算力 | ≈ 850 EH/s（已从 2025-10 峰值 1,160 EH/s 回落） |
| 全网难度 | ≈ 126 T（2026-10-15 刚下调 11.16%；历史峰值 155.97 T） |
| 全网日产出 | 450 BTC/天（144 × 3.125） |
| 一台蚂蚁 S21 | 200 TH/s，功耗 3.5 kW，售价约 $4,000 |

单台 S21 的份额 = 200 / (850×10⁶) ≈ **0.0000235%**，期望日收入 =
450 × 0.000000235 × $82,000 ≈ **$8.7/天**。

电费（84 kWh/天）才是分水岭：

| 电价场景 | 日电费 | 日净利 |
|---|---|---|
| 英国居民电价（Ofgem 2026 Q4 上限 26.32p/kWh） | ≈ $28 | **≈ −$19（亏）** |
| 美国工业电价（约 $0.045/kWh） | ≈ $3.8 | ≈ +$4.9（回本仍需 ~800 天，且难度只增不减） |
| 自有廉价电 / 弃电（≈ $0.01/kWh） | ≈ $0.8 | ≈ +$7.9 |

**结论（泼冷水版）**：在普通居民电价下，挖矿的数学期望是**净亏损**——你在英国
这种电价环境里买任何矿机都是负 EV。真正赚钱的只有两类人：拿到 $0.03/kWh 以下
工业电价的规模化矿场（且通常用期权锁价对冲），以及 2010-2013 年全网算力还只有
现在的几十亿分之一时的早期矿工。此外每 4 年减半（下次 2028 年，出块奖励降到
1.5625 BTC）会再腰斩一次收入，而新矿机上市又把全网难度推高。"挖矿能赚钱"
这句话对散户几乎总是错的，这就是为什么专业矿场都在冰岛/美国德州/中东找电。

## 四、比特币存在哪里？以什么形式？

- 比特币**不存在任何"币文件"里**。它只是**分布式账本**（distributed ledger）上
  的一串记录：全网每台全节点保存一份完整的区块链副本。
- 单位形式是 **UTXO（Unspent Transaction Output，未花费交易输出）**：一笔
  "地址 A 转给地址 B 3.2 BTC" 的交易，会把 A 的输出标记为已花费，并给 B 创建
  一个 3.2 BTC 的新 UTXO。所谓"你有 3.2 BTC" = "账本上有 3.2 BTC 的 UTXO
  用你的地址锁定"。
- 谁控制它？**私钥（private key）**。地址 = 公钥的哈希；任何人持有私钥就能签名
  花费对应的 UTXO。钱包软件只是私钥的保管/签名工具，丢了私钥 = 币永久消失
  （全网没有任何"找回"机制）。
- 挖矿在其中的位置：矿工通过 PoW 竞争**记账权**——谁先解出有效哈希，谁就有权
  把打包好的区块（含新交易）写入账本，并获得系统凭空造出的 coinbase 奖励 +
  区块内交易费。这就是"挖矿赚钱"的唯一来源：**出售记账权和铸币权**。

## 五、"任何货币的挖矿"：不同币完全不一样

| 币种 | 共识 | 哈希算法 | 典型硬件 | 备注 |
|---|---|---|---|---|
| 比特币 BTC | PoW | SHA-256（双重） | ASIC 矿机 | 全网算力数百 EH/s，散户无机会 |
| 莱特币 LTC | PoW | Scrypt | ASIC | 早期为"抗 ASIC"设计，已被 ASIC 攻克 |
| 狗狗币 DOGE | PoW | Scrypt | ASIC（与 LTC 合并挖矿） | 无限增发 |
| 门罗币 XMR | PoW | RandomX | **CPU** | 强 ASIC 抗性，专为 CPU 设计 |
| 卡斯帕 KASPA | PoW | kHeavyHash | GPU | 区块 DAG，高吞吐 |
| 以太坊 ETH | PoS | （历史 Ethash/GPU） | 无挖矿 | 2022-09 起转 PoS，挖矿被质押替代 |
| SOL / ADA / DOT | PoS | — | 无挖矿 | 质押（staking）锁币赚利息 |
| USDT / USDC | 中心化 | — | 无 | 稳定币，靠储备金/增发，不挖矿 |

一句话：**PoW 才需要"挖"**；PoS 是"质押"，稳定币/中心化币根本不产矿。

## 六、CPU / GPU / ASIC 适配是怎么回事

- **ASIC**（专用集成电路）：SHA-256 矿机就是一块只为算 sha256 设计的芯片，
  算力是 GPU 的几十万倍，但只能挖 SHA-256 系（BTC/LTC/DOGE 各自专用）。
- **GPU**：通用并行核（几千个 CUDA/OpenCL 核心），适合 Ethash/kHeavyHash 这类
  内存依赖算法；模拟器里用 4 条线程流模拟这种并行（真实是上万核并行）。
- **CPU**：算力最弱，只适合 RandomX 这类刻意把 GPU/ASIC 拒之门外的 CPU 算法。
- 模拟器不真的调用 GPU（Python 也没有可移植的 CUDA 接口），它演示的是**搜索
  过程的并行分片逻辑**：把 nonce 空间按 lane 切分、各自独立扫描——这正是
  真实矿工在 GPU 上做的事。

## 七、安全与合规边界

- 本程序只监听 `127.0.0.1`，不连接任何矿池 / 交易所 / 外部节点；`/stats` 只读。
- 每次哈希之间强制睡眠，实测 CPU 占用接近 0%，不做任何真实挖矿。
- **不要把它改造成"隐藏挖矿"脚本**：在未授权机器上挖矿（cryptojacking）在世界
  绝大多数司法辖区都是犯罪，且会立刻被安全软件识别。
- 真实挖矿请走正规矿池与硬件，先算清电费账；本仓库仅用于理解 PoW 原理。
